## Что нужно знать про «частично»

Три майлстоуна закрыты не полностью, и причина у каждого записана в ADR.
**Не пытайся их «дозакрыть» по своей инициативе** — там нужен человек
или ключ API.

**M3.** Эталон извлечения (`data/evals/extraction_gold.jsonl`, 40 записей)
размечен моделью `claude-opus-5`, а не человеком. Правило 6 брифа нарушено
по прямому указанию владельца. Провенанс машиночитаемый: поле `annotator`
в каждой записи, отчёт печатает предупреждение над таблицей, подпись
эталона выводится из записей («эталон (МОДЕЛЬ)»). Оба вопроса M2 остались
открытыми. Лечится переразметкой руками: `rm data/evals/extraction_gold.jsonl`
и `nutri-radar evals annotate --annotator "<имя>" --lang ru`.

**M5.** 20 эталонных запросов (`data/retrieval/queries.jsonl`) составил
ассистент, `author: sql-oracle`. Смягчение: эталон не зависит от
оцениваемой системы — формулировки словами, верные ответы выводит SQL.
Плановый recall@5 оказался неверной метрикой (дал 0,0% у любой системы,
потому что под условие подходят тысячи продуктов) и заменён на долю выдачи
с запрошенным свойством — 47,0%.

**M6.** Агент прогнан на `qwen2.5:3b` вместо Sonnet 5. Выбор инструмента
работает на 100% (первым вызовом, 10 из 10), завершение цикла — на 20%.

**Общая причина двух из трёх — нет `ANTHROPIC__API_KEY`.** Один ключ
разблокирует M6, облачную часть M3 и гибрид из ADR-009. Механика везде
собрана и покрыта тестами: понадобится только `LLM__PROVIDER=anthropic`.

## Как тут заведено

Это важнее, чем кажется: правила проекта соблюдались все семь майлстоунов,
и ломать их не надо.

1. **Замер до прогона.** Любая длинная операция начинается с замера
   на 200 единицах и экстраполяции. Так было в M2, M4, M5 — и каждый раз
   решение о размере корпуса принималось по числу, а не по плану.
2. **Ожидание записывается ДО прогона.** В плане M6 заранее записано, что
   3B, скорее всего, не справится. Когда так и вышло, это стало измерением,
   а не оправданием.
3. **Плохое число публикуется как есть.** M4: локальная LLM оказалась хуже
   строчки `return "e"`. M6: агент дошёл до ответа в 20%. Оба опубликованы.
4. **Метрику проверяй до публикации.** Дважды за проект метрика была
   неверной и давала «плохой» результат, который был ошибкой постановки,
   а не системы: recall@5 в M5 (0,0% у любой системы) и «использовал
   инструмент» в M6 (засчитало бы перебор). Если число выглядит слишком
   плохим или слишком хорошим — сначала проверь метрику.
5. **Эталонную разметку делает человек** (правило 6). Дважды нарушено
   по прямому указанию владельца, и оба раза провенанс записан честно.
   Сам такое не решай.
6. **Защита структурная, а не промптовая.** `sql_query` — единственное
   место, где текст модели идёт в базу; там read-only транзакция и белый
   список, а не просьба «не пиши DELETE».
7. **Каждое решение — в `DECISIONS.md`** в формате контекст → решение →
   альтернативы → последствия. Их уже 30.
8. **Коммит на каждый логический шаг**, Conventional Commits, по-русски.

## Грабли, на которые уже наступили

- **`/dev/shm` в Docker — 64 МБ.** Сборка индекса HNSW падает с «No space
  left on device» при свободном терабайте. Причём shm обязана быть **больше**
  `maintenance_work_mem`, а не равна: на 1 ГБ при лимите 2 ГБ тоже падает.
  Стоит 4 ГБ в `docker-compose.yml`.
- **Каст к `halfvec` обязан быть явным.** Без него Postgres считает тип
  за `vector`, класс операций индекса не совпадает, и запрос **молча**
  уходит в полный перебор, возвращая правильный ответ. Проверяется через
  `explain_search` / `uses_index`.
- **36% корпуса приходит с HTML** `<span class="allergen">`. В `retrieval`
  снимается; в M2 и M3 модель это видела.
- **Консоль Windows однобайтная.** Вывод текстов на пяти языках нужно
  прогонять через `_printable`, иначе французское `é` роняет команду.
- **Негативные шаблоны в `.gitignore` не работают**, если каталог исключён
  как `/dir/`, а не `/dir/*`. Правило `!/reports/baseline/` не срабатывало
  с M0.
- **Фоновый цикл ожидания надо доводить до конца.** В ночную сессию был
  запущен `until grep -q "..." reports/m4_sanity_nova.log; do sleep 30; done`,
  а файл потом пересоздали под другим именем. Условие стало недостижимым,
  и цикл крутился трое суток. Правило: не вешать ожидание на файл, который
  сам же собираешься заменить, и проверять завершение фоновой задачи,
  а не предполагать его.
- **Heredoc в Bash съедает обратный слеш.** Для записи `"\n"` в Python-файл
  через heredoc используй `chr(92)`, иначе получишь настоящий перенос строки
  внутри литерала и синтаксическую ошибку. На M7 наступили дважды —
  надёжнее писать такие файлы инструментом записи, а не heredoc.
- **`git merge -F -` не читает сообщение из stdin.** Ошибка «could not read
  file '-'», а ветка при этом уже переключена. Сообщение — во временный файл.
- **Сравнивать `id()` объектов, чьи времена жизни не пересекаются, нельзя.**
  CPython переиспользует адреса освобождённых, и тест проходит или падает
  в зависимости от истории аллокаций в прогоне: в одиночку зелёный, в полном
  наборе красный. Держи ссылки на оба объекта и сравнивай их самих.
- **`mypy` был красным с M2 и никто не знал**, потому что CI не запускался.
  Проверяй перед пушем ровно то, что делает CI, а не подмножество.
- **Мажорные версии приезжают молча.** `mcp>=1.2` поставил 2.x, где FastMCP
  переименован в MCPServer; `zxing-cpp` 3.1 объявил устаревшим объединение
  форматов через `|`, а `filterwarnings = ["error"]` превращает это в упавший
  тест. Пин должен отражать API, под который написан код.
- **FastAPI 0.141 заворачивает роутеры в `_IncludedRouter`.** Обход
  `app.routes` не покажет эндпойнты; авторитетна схема `/openapi.json`.

## Что запускать

```bash
docker compose up -d db                    # база; том food_pgdata цел
uv run nutri-radar health                  # проверка окружения
uv run pytest -q                           # 714 тестов, без докера и сети
uv run pytest -m integration -q            # 26 тестов, нужна поднятая БД

uv run nutri-radar retrieval search "шоколад без пальмового масла"
uv run nutri-radar agent ask "что за продукт 3017620425035"
uv run nutri-radar agent evaluate          # прогон по 10 вопросам

# Витрина M7
uv run nutri-radar serve api               # http://localhost:8000/docs
uv run nutri-radar serve bot               # нужен BOT__TOKEN
uv run nutri-radar serve mcp               # stdio, запускает клиент
docker compose up -d api                   # поднимет и базу
```

Ollama нужна для `retrieval` и `agent`: модели `qwen2.5:3b-instruct-q4_K_M`
и `bge-m3` уже загружены.
