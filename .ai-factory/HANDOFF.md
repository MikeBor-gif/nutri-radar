## Что нужно знать про «частично»

Три майлстоуна закрыты не полностью, и причина у каждого записана в ADR.
**Не пытайся их «дозакрыть» по своей инициативе** — там нужен человек
или ключ API.

**M3.** Эталон извлечения (`data/evals/extraction_gold.jsonl`, 40 записей)
размечен моделью `claude-opus-5`, а не человеком. Правило 6 брифа нарушено
по прямому указанию владельца. Провенанс машиночитаемый: поле `annotator`
в каждой записи, отчёт печатает предупреждение над таблицей, подпись
эталона выводится из записей («эталон (МОДЕЛЬ)»). Оба вопроса M2 остались
открытыми. Лечится переразметкой руками: `rm data/evals/extraction_gold.jsonl`
и `nutri-radar evals annotate --annotator "<имя>" --lang ru`.

**M5.** 20 эталонных запросов (`data/retrieval/queries.jsonl`) составил
ассистент, `author: sql-oracle`. Набор из 20 вопросов вне домена
(`data/retrieval/out_of_domain.jsonl`) тоже составил ассистент, по прямому
указанию владельца: верного ответа у этих вопросов нет по определению,
ожидаемое поведение одно на весь файл — отказ, и размечать в них нечего. Смягчение: эталон не зависит от
оцениваемой системы — формулировки словами, верные ответы выводит SQL.
Плановый recall@5 оказался неверной метрикой (дал 0,0% у любой системы,
потому что под условие подходят тысячи продуктов) и заменён на долю выдачи
с запрошенным свойством — 47,0%.

**M6.** Агент прогнан на `qwen2.5:3b` вместо Sonnet 5. Выбор инструмента
работает на 100% (первым вызовом, 10 из 10), завершение цикла — на 20%.

**Общая причина двух из трёх — нет `ANTHROPIC__API_KEY`.** Один ключ
разблокирует M6, облачную часть M3 и гибрид из ADR-009. Механика везде
собрана и покрыта тестами: понадобится только `LLM__PROVIDER=anthropic`.

## Что осталось открытым

Это не «доделать код» — код работает. Это незакрытая доказательная база,
и стоимость каждого пункта известна.

**1. Оценка качества извлечения не получена.** Самый уязвимый пункт: на
вопрос «какое качество у вашего извлечения» ответа сейчас нет. Эталон
(`data/evals/extraction_gold.jsonl`, 40 записей) размечен моделью
`claude-opus-5`, а не человеком, и ошибки разметчика коррелируют с ошибками
оцениваемой системы. Единственный незакрытый чекбокс во всех восьми планах —
задача 10 в `0004_feature-m3-evals.md`, и она **для владельца, не для
ассистента** (правило 6 брифа).

```bash
rm data/evals/extraction_gold.jsonl
uv run nutri-radar evals annotate --annotator "<имя>" --lang ru
```

Стоимость — один вечер. Закрывает заодно оба вопроса M2, которые на машинном
эталоне неразличимы.

**2. «Агент решает задачи» не доказано.** Нужен `ANTHROPIC__API_KEY`.
Механика собрана и покрыта тестами: понадобится только
`LLM__PROVIDER=anthropic`. Тот же ключ разблокирует облачную часть M3
и отложенный гибрид из ADR-009.

**3. Эталон поиска не человеческий** (20 запросов, `author: sql-oracle`).
Смягчение: эталон не зависит от оцениваемой системы — формулировки словами,
верные ответы выводит SQL.

**4. ~~Бот не прогонялся против живого Telegram~~ — закрыто 11.09.2026.**
Прогон состоялся и нашёл три дефекта, которых не нашли 714 тестов
(все три исправлены, коммит `93fa3ca`). Разбор — ADR-031, решение 8.
Подтвердились: `zxing-cpp` 64 мс на реальном фото упаковки, атрибуция
ODbL и дисклеймер первым сообщением, 30 форм сахара в карточке из корпуса.

**5. Отказ на вопросах вне домена — 15,0%, дефект измерен и не исправлен.**
Система отвечает на «составь мне меню на неделю» и «какой шоколад можно
есть при диабете» — это прямо за границами продукта из брифа. По рецептам,
доставке и личным советам по питанию отказов нет вовсе. Порог
`MIN_SIMILARITY` тут не помощник: «сколько стоит хлеб» находит хлеб
с высокой близостью. Починка требует классификатора домена вопроса
со своим эталоном, а эталон размечает человек (правило 6). Решение
не чинить — осознанное, ADR-032, решение 3.

## Как тут заведено

Это важнее, чем кажется: правила проекта соблюдались все семь майлстоунов,
и ломать их не надо.

1. **Замер до прогона.** Любая длинная операция начинается с замера
   на 200 единицах и экстраполяции. Так было в M2, M4, M5 — и каждый раз
   решение о размере корпуса принималось по числу, а не по плану.
2. **Ожидание записывается ДО прогона.** В плане M6 заранее записано, что
   3B, скорее всего, не справится. Когда так и вышло, это стало измерением,
   а не оправданием.
3. **Плохое число публикуется как есть.** M4: локальная LLM оказалась хуже
   строчки `return "e"`. M6: агент дошёл до ответа в 20%. Оба опубликованы.
4. **Метрику проверяй до публикации.** Трижды за проект метрика была
   неверной и давала «плохой» результат, который был ошибкой постановки,
   а не системы: recall@5 в M5 (0,0% у любой системы), «использовал
   инструмент» в M6 (засчитало бы перебор) и доля ответов на языке
   вопроса в доводке витрины (70,0% вместо 76,5%: немецкие и французские
   запросы попадали в промахи, потому что признак по алфавиту их
   от английского не отличает). Если число выглядит слишком плохим
   или слишком хорошим — сначала проверь метрику.
5. **Эталонную разметку делает человек** (правило 6). Трижды отступали
   по прямому указанию владельца, и каждый раз провенанс записан честно:
   эталон извлечения M3, эталонные запросы M5 и вопросы вне домена
   в доводке витрины. Последний случай мягче остальных — у этих вопросов
   нет верного ответа, размечать в них нечего, — но спросить всё равно
   пришлось. Сам такое не решай.
6. **Защита структурная, а не промптовая.** `sql_query` — единственное
   место, где текст модели идёт в базу; там read-only транзакция и белый
   список, а не просьба «не пиши DELETE».
7. **Каждое решение — в `DECISIONS.md`** в формате контекст → решение →
   альтернативы → последствия. Их уже 33.
8. **Провалившийся эксперимент не удаляется.** `rag_v2` лежит в репозитории
   вместе с числами, которые показали, что он хуже `rag_v1`. Оставить только
   то, что получилось, значило бы обречь следующего читателя повторить
   эксперимент с нуля: идея выглядит разумной, и она разумная.
9. **Коммит на каждый логический шаг**, Conventional Commits, по-русски.

## Грабли, на которые уже наступили

- **`/dev/shm` в Docker — 64 МБ.** Сборка индекса HNSW падает с «No space
  left on device» при свободном терабайте. Причём shm обязана быть **больше**
  `maintenance_work_mem`, а не равна: на 1 ГБ при лимите 2 ГБ тоже падает.
  Стоит 4 ГБ в `docker-compose.yml`.
- **Каст к `halfvec` обязан быть явным.** Без него Postgres считает тип
  за `vector`, класс операций индекса не совпадает, и запрос **молча**
  уходит в полный перебор, возвращая правильный ответ. Проверяется через
  `explain_search` / `uses_index`.
- **36% корпуса приходит с HTML** `<span class="allergen">`. В `retrieval`
  снимается; в M2 и M3 модель это видела.
- **Консоль Windows однобайтная.** Вывод текстов на пяти языках нужно
  прогонять через `_printable`, иначе французское `é` роняет команду.
- **Негативные шаблоны в `.gitignore` не работают**, если каталог исключён
  как `/dir/`, а не `/dir/*`. Правило `!/reports/baseline/` не срабатывало
  с M0.
- **Фоновый цикл ожидания надо доводить до конца.** В ночную сессию был
  запущен `until grep -q "..." reports/m4_sanity_nova.log; do sleep 30; done`,
  а файл потом пересоздали под другим именем. Условие стало недостижимым,
  и цикл крутился трое суток. Правило: не вешать ожидание на файл, который
  сам же собираешься заменить, и проверять завершение фоновой задачи,
  а не предполагать его.
- **Heredoc в Bash съедает обратный слеш.** Для записи `"\n"` в Python-файл
  через heredoc используй `chr(92)`, иначе получишь настоящий перенос строки
  внутри литерала и синтаксическую ошибку. На M7 наступили дважды —
  надёжнее писать такие файлы инструментом записи, а не heredoc.
- **`git merge -F -` не читает сообщение из stdin.** Ошибка «could not read
  file '-'», а ветка при этом уже переключена. Сообщение — во временный файл.
- **Сравнивать `id()` объектов, чьи времена жизни не пересекаются, нельзя.**
  CPython переиспользует адреса освобождённых, и тест проходит или падает
  в зависимости от истории аллокаций в прогоне: в одиночку зелёный, в полном
  наборе красный. Держи ссылки на оба объекта и сравнивай их самих.
- **`mypy` был красным с M2 и никто не знал**, потому что CI не запускался.
  Проверяй перед пушем ровно то, что делает CI, а не подмножество.
- **То же правило, второй раз, дороже.** Защита от утечки секретов
  (автоюзная фикстура `_no_real_secrets`) и интеграционные тесты тянут
  окружение в разные стороны: первой нужно затереть `DB__PASSWORD`, вторым —
  получить настоящий. Конфликт виден только прогоном с поднятой базой,
  локально гоняли `pytest -q` — и он молчал. CI был красным два прогона,
  а в этой записке стояло «CI зелёный». ADR-033.
- **Пустая строка в переменной окружения — не то же самое, что её отсутствие.**
  В pydantic-settings переменная приоритетнее `.env`, поэтому `KEY=""`
  не «оставляет значение из файла», а перекрывает его пустотой.
- **Мажорные версии приезжают молча.** `mcp>=1.2` поставил 2.x, где FastMCP
  переименован в MCPServer; `zxing-cpp` 3.1 объявил устаревшим объединение
  форматов через `|`, а `filterwarnings = ["error"]` превращает это в упавший
  тест. Пин должен отражать API, под который написан код.
- **FastAPI 0.141 заворачивает роутеры в `_IncludedRouter`.** Обход
  `app.routes` не покажет эндпойнты; авторитетна схема `/openapi.json`.
- **`qwen2.5:3b-instruct-q4_K_M` на русском уходит в вырожденный повтор.**
  Полезный ответ кончается на четвёртом предложении, дальше одна фраза
  до упора в `num_predict`, JSON обрывается, разбор падает. Правило
  «не повторяй себя» в промпте не помогает: модель повторяет себя ровно
  теми предложениями, которые правило запрещает. Отсюда и провал `rag_v2`.
  `repeat_penalty` не трогали намеренно — параметр общий для всех вызовов,
  а на них посчитаны метрики M2 и M3.
- **Метрика по алфавиту не различает языки одной письменности.** Признак
  «кириллица против латиницы» на немецком и французском отвечает
  «английский» всегда, и первая версия метрики языка записывала такие
  запросы в промахи: 70,0% вместо 76,5%. Языки, которые признак реально
  различает, обязаны быть перечислены явно, а остальные — выведены
  из знаменателя, а не засчитаны как ошибки системы.

## Что запускать

```bash
docker compose up -d db                    # база; том food_pgdata цел
uv run nutri-radar health                  # проверка окружения
uv run pytest -q                           # 766 тестов, без докера и сети
uv run pytest -m integration -q            # 28 тестов, нужна поднятая БД
uv run pytest -m "" -q                     # все 794 одним процессом

uv run nutri-radar retrieval search "шоколад без пальмового масла"
uv run nutri-radar agent ask "что за продукт 3017620425035"
uv run nutri-radar agent evaluate          # прогон по 10 вопросам

uv run nutri-radar retrieval evaluate           # язык ответа и отказ вне домена
uv run nutri-radar retrieval switch-benchmark   # цена переключения модели

# Витрина M7
uv run nutri-radar serve api               # http://localhost:8000/docs
uv run nutri-radar serve bot               # нужен BOT__TOKEN
uv run nutri-radar serve mcp               # stdio, запускает клиент
docker compose up -d api                   # поднимет и базу
```

Ollama нужна для `retrieval` и `agent`: модели `qwen2.5:3b-instruct-q4_K_M`
и `bge-m3` уже загружены.

## Чего не делать

- Не выкачивать базу OFF через API — только дампом. `lookup_barcode` —
  единственное разрешённое место.
- Не тащить LangChain / LlamaIndex / CrewAI: агент написан руками, и это
  предмет демонстрации.
- Не генерировать эталонную разметку для evals по своей инициативе.
- Не делать веб-фронтенд, не дообучать модели.
- Не переходить к следующему майлстоуну без слова владельца (правило 2).
